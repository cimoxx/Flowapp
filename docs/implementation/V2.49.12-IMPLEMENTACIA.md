# Flow v2.49.12 – pravidelné platby

## Príčina duplicít
Frontend generoval transakcie s `isRecurring`, `frequency` a `recurringPlanId`, ale Google Apps Script zapisoval do Sheet1 iba prvých 16 polí. Po cloud pull synchronizácii sa tieto tri polia stratili.

Následne `processRecurringPayments()` nevedel nájsť už existujúcu occurrence a vytvoril novú. Pri editácii plánu sa pôvodná transakcia bez `recurringPlanId` nedala spojiť s plánom a vznikla ďalšia.

## Oprava
Sheet1 má nové stĺpce:
- Q `isRecurring`
- R `frequency`
- S `recurringPlanId`

Generátor:
- používa stabilné ID `RPOCC_<planId>_<date>`,
- najprv hľadá už existujúcu occurrence,
- vie opraviť staré `tx_*` generované položky, ktoré stratili metadata,
- pri viacerých generator-shaped položkách pre rovnaký plán/dátum ponechá jednu a ostatné označí na delete,
- nikdy automaticky nemaže bežné používateľské `ID-*` transakcie.

## Editácia
Pri voľbe budúce/všetky sa existujúce generované transakcie upravia na mieste a zachovajú `isRecurring=true` + `recurringPlanId`.

## UX
Lokálny plán sa uloží a vykreslí okamžite. Cloud save beží následne a používateľ dostane okamžitý toast aj finálny stav.
